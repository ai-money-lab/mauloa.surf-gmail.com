# パイプライン自動進化

X投稿パイプラインの比率を実績データに基づき自動最適化する。

## 引数
- `$ARGUMENTS`: オプション（例: "dry-run" でシミュレーションのみ）

## 実行手順

1. **パフォーマンスデータ収集**:
   - `data/` 配下の投稿実績データを読み込む
   - 各パイプライン（buzz/data-driven/original）のエンゲージメント率を集計
   - 直近7日 / 30日の推移を把握

2. **現在の比率を確認**:
   - `config/config.yaml` の `system_a.pipeline_ratio` を読み取り
   - 現在値: buzz={n}% / data={n}% / original={n}%

3. **最適比率を算出**:
   - エンゲージメント率が高いパイプラインの比率を上げる
   - ただし制約を遵守:
     - 各パイプライン最低15%、最大60%
     - 1週間の調整幅は最大10%ポイント
     - 合計は必ず100%
   - `system_a/analyze_performance.py` のロジックを参考に

4. **変更提案**:
   ```
   ═══════════════════════════════════════════════
    ASCEND — パイプライン進化提案
   ═══════════════════════════════════════════════

   現在の比率:
     buzz:     {current}% → {proposed}% ({diff})
     data:     {current}% → {proposed}% ({diff})
     original: {current}% → {proposed}% ({diff})

   根拠:
   - {パイプライン名}: エンゲージメント率 {n}%（{上昇/下降}傾向）
   - ...

   ═══════════════════════════════════════════════
   ```

5. **適用**:
   - dry-runでなければ `config/config.yaml` を更新
   - 変更前後の差分を表示
   - 「この変更をコミットする？」とユーザーに確認
